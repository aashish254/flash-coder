# Privacy and data handling

Everything here is stated so you can check it in the source, because a privacy
page that asks for trust is worth nothing. The two claims that matter:

- **Nothing runs on a server.** There is no account, no API key, no licence
  call, no update ping, no analytics client. `grep -rn "requests\." flash/`
  finds one network call in the whole package — `flash/web.py`, which fetches
  the documentation URL *you* passed to `flash web`. Model weights come from
  Hugging Face through `mlx-lm`'s downloader, once per model, into your own
  cache directory.
- **Your code stays in the directories you can see**, listed below, and the
  default record is a digest rather than your source text.

## What leaves the machine

| when | what goes out | who asked |
| --- | --- | --- |
| first `flash run` with an uncached model | the model repo is downloaded from Hugging Face | you, by running a command that generates text |
| `flash web <url>` | one HTTPS GET for that URL | you, naming the URL |
| `pip install` | the usual package index traffic | you, installing |

That is the list. `flash/doctor.py` prints which of the four §22 models are
already in your cache, so a surprise download is visible before it happens
rather than during a run.

## What gets written to disk

| path | contents | default |
| --- | --- | --- |
| `benchmarks/results/traces/` | one JSONL session per run: stages, token counts, tier, verifier result, timings | **no prompt or response text** |
| the same files, with `--trace-full` | prompt and model output text ride along, for replay | only if you pass the flag |
| `benchmarks/results/datasets/` | SFT pairs mined from the trace store, plus a manifest naming everything excluded for leakage | only if you run `python -m flash.train --dataset` |
| `benchmarks/results/jobs/`, `adapters/` | resumable job state and LoRA checkpoints | only if you run `flash learn --lora` |
| `~/.flash/ambient/` | draft worktrees, and the log every ambient-mode safety claim reads | only for `flash ambient` |
| `benchmarks/cache/` | the text `flash web` fetched, keyed by a hash of the URL, so a re-run does not re-fetch | only for `flash web`; gitignored and regenerable |

Two consequences worth being explicit about. The training dataset is mined from
traces, so if you ran with `--trace-full` against a private repository and then
built a dataset, your source text is in `benchmarks/results/datasets/` — that
directory is the one to delete first. And `flash train --dry-run` writes
nothing at all, which since R-7.9 is a gated statement rather than an
expectation.

To remove everything the tool has ever learned locally:

```bash
rm -rf benchmarks/results/traces benchmarks/results/datasets
rm -rf ~/.flash/ambient
```

Weights live wherever `HF_HOME` points; `flash doctor` prints that resolved
path, and deleting it is how you get the disk back.

## Execution: the verifier is code you supplied

`flash run --test FILE` answers "did it work?" by executing `python FILE`. That
file is chosen by you, not generated by the model, and it runs with your user's
permissions — a task whose verifier reads `~/.ssh` would read `~/.ssh`. This is
why the harness runs candidate edits and every verification through
`flash/sandbox.py`: a Seatbelt profile that denies outbound sockets (DNS
included) and file writes outside the root it was handed, plus CPU/size
rlimits. `python -m flash.sandbox --selftest` measures the enforcement rather
than asserting it — on this machine it reports `seatbelt=enforced`, and the
memory ceiling line reports honestly when the kernel refuses to grant one.

The sandbox is not a container and the page does not claim it is: it is
unprivileged-code-does-not-leave-its-lane, which is what a candidate patch
needs and less than what a hostile verifier needs. If you would not run a
`--test` file by hand, do not run it through `flash`.

## This repository's own records

180 files under `benchmarks/results/` are committed (194 exist on disk; the rest
are this pass's own outputs), and they are the reason the numbers in `SPEC.md`
can be checked instead of believed. They contain
prompts and outputs from this project's own benchmark suites — synthetic tasks
and `benchmarks/fixtures/`, never a user's repository — which is also why
`docs/portability.md` tolerates 411 absolute-path occurrences inside records
and gates every path outside them. A record whose text had been rewritten to
look portable would no longer be a record, so the exclusion is listed group by
group and a new record directory fails the gate until the document says why it
is one.

## What was swept before this was published

Because a privacy page is the place a reader looks *after* the damage, the
sweep is the thing to point at instead:
`python benchmarks/publish_secret_scan.py` reads every file a `git push` would
send (working tree, including files not yet tracked) **and every blob ever
committed**, against seven credential shapes plus key-file filenames, and
refuses to call itself clean unless each pattern can match — it plants a
synthetic secret in every family and exits 1 if any family passes it.

The run that shipped this page printed: **359 files in the working tree (4 not
yet tracked) and 713 historical blobs**, **2 matches, both named with the
reason they are not credentials, 0 unlisted**, **21 NUL-padded blobs swept with
their padding removed rather than skipped**, and identity counts of
**7** occurrences of the author's GitHub noreply address, **0** personal email
addresses, and **1117** host paths. That last count is not the one
`docs/portability.md` argues about: it counts every occurrence in the working
tree *and in every blob ever committed*, while the portability page's **411** is
the residue in the 188 record files that gate reads, once the history blobs and
the decompressed archive members are left out. The two numbers measure
different sets, and `docs/portability.md` explains why the records keep their
paths at all. The witness is
`benchmarks/results/publish_secret_scan_20260928.log`. Those two counts belong to that
run, not to the repository forever: every commit adds blobs to the history arm, so the
same command on the commit that carried this page printed **735** historical blobs and
**0** untracked files. A bigger number when you re-run it is the history growing, not
this claim failing.

The two accepted matches, since "trust me" is not an answer here either: the
OpenAI key aider is handed in `benchmarks/market_compare.py` is the literal
`proxy-no-auth` for a local server that authenticates nobody, and the
credential-shaped run in `site/package-lock.json` is a base64 stretch inside an
`sha512-…==` integrity hash, which is a content digest of a published npm
tarball.

Two limits worth stating plainly. It is a pattern sweep, not a proof of
absence — it finds the shapes credentials have, so a secret written in a shape
nobody has named would pass. And it sweeps what a push sends: a gitignored file
is not in scope, unless it gets force-added, which is why the working-tree arm
runs over `git ls-files --others --exclude-standard` rather than the tip alone.

`python benchmarks/publish_secret_scan.py` is not one of the §6 battery's lines,
and the reason is honest rather than convenient: its history arm needs `.git`,
so an unpacked sdist cannot run it. It is cited, not counted.

## Telemetry

None. There is no code path that reports a run, a failure or an install
anywhere, and no build-time or import-time network call: `flash/__init__.py`
imports no backend, and `benchmarks/backend_free_check.py` proves every module
of the package imports with the model backend blocked. If that ever changes,
the change belongs in this page in the same commit.
